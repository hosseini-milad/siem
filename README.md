# بک‌اند SIEM — فاز اول

API پایتون با **FastAPI + MongoDB** برای دریافت و ذخیرهٔ لاگ. تمام عملیات داده از Swagger انجام می‌شود؛ نیازی به دستور کنسولی برای ثبت یا جست‌وجوی لاگ نیست. دستورات زیر فقط برای نصب و راه‌اندازی سرویس‌ها هستند.

این نسخه احراز هویت، هوش مصنوعی، Logstash، Elasticsearch یا Kibana ندارد. پنل مخزن `spectral_panel` تغییر نکرده است. MongoDB محل اصلی نگهداری داده است؛ Elasticsearch در فاز بعد نمای جست‌وجو خواهد بود و جای MongoDB را نمی‌گیرد.

## نصب و اجرا

پیش‌نیاز: Python 3.12 یا جدیدتر و Docker Compose با daemon فعال.

```bash
cd /workspace/siem
python -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
docker compose up -d --wait mongodb
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

`requirements.lock` نسخه‌های دقیق محیط آزمایش‌شده، شامل ابزارهای تست را نگه می‌دارد. در محیط کلاد در صورت نیاز به کش قابل نوشتن، به pip گزینهٔ `--cache-dir /workspace/.pip-cache` بدهید.

در مرورگر همان سرور مسیر `/docs` روی پورت ۸۰۰۰ را باز کنید. مسیر `/` نیز به Swagger هدایت می‌شود و قرارداد OpenAPI در `/openapi.json` قرار دارد. فایل‌های رابط Swagger به‌صورت پیش‌فرض FastAPI از CDN بارگذاری می‌شوند و مرورگر برای آن‌ها به اینترنت نیاز دارد.

تنظیمات اختیاری را از `.env.example` در `.env` کپی کنید؛ پیش‌فرض اتصال `mongodb://127.0.0.1:27017` و دیتابیس `siem` است. متغیرهای `SIEM_MONGODB_URI` و `SIEM_MONGODB_DATABASE` نیز پشتیبانی می‌شوند. اطلاعات اتصال محرمانه را commit نکنید.

MongoDB فقط روی loopback منتشر می‌شود و داده‌ها در volume نام‌دار `siem_mongo_data` باقی می‌مانند. `docker compose down` داده‌ها را نگه می‌دارد؛ گزینهٔ `-v` داده‌ها را حذف می‌کند. این تنظیم توسعه‌ای بدون احراز هویت است؛ برای دسترسی بیرونی آماده نیست. برنامه هنگام شروع اتصال MongoDB و ایجاد ایندکس‌ها را بررسی می‌کند؛ اگر دیتابیس در دسترس نباشد شروع برنامه شکست می‌خورد.

## اولین کار با Swagger

۱. بخش **Health**، اکشن `GET /api/v1/health` را باز کنید و `Try it out` و سپس `Execute` را بزنید. نتیجه باید `status: ok` و `database: mongodb` باشد.

۲. در بخش **Logs**، اکشن `POST /api/v1/logs` را باز کنید و این ورودی را اجرا کنید:

```json
{
  "timestamp": "2026-11-16T10:00:00Z",
  "source": "firewall-01",
  "level": "WARNING",
  "message": "Connection denied",
  "attributes": {
    "source_ip": "192.0.2.10",
    "destination_ip": "192.0.2.20",
    "port": 22
  }
}
```

پاسخ `201` شامل دادهٔ ذخیره‌شده، `id` و زمان دریافت `received_at` است. هر درخواست موفق یک شناسهٔ جدید می‌سازد؛ ارسال مجدد حذف تکرار ندارد.

۳. `GET /api/v1/logs` را اجرا کنید تا رکورد ذخیره‌شده را از MongoDB بخوانید. با `source`، `level`، `start` و `end` فیلتر کنید. بازهٔ زمان روی `timestamp` رویداد اعمال می‌شود و دو سر بازه را شامل می‌شود. `limit` بین ۱ تا ۱۰۰ و `offset` بین صفر تا ۱۰۰۰۰۰ است. پاسخ `items`، `total`، `limit` و `offset` دارد و بر اساس زمان نزولی مرتب می‌شود.

۴. شناسهٔ پاسخ مرحلهٔ ۲ را در `GET /api/v1/logs/{log_id}` قرار دهید. شناسهٔ ناموجود `404` و ورودی نامعتبر `422` برمی‌گرداند.

۵. برای ورود گروهی، `POST /api/v1/logs/batch` را با بدنهٔ زیر اجرا کنید:

```json
{
  "events": [
    {
      "timestamp": "2026-11-16T10:00:00Z",
      "source": "router-01",
      "level": "INFO",
      "message": "Interface up",
      "attributes": {"interface": "eth0"}
    }
  ]
}
```

ورودی گروهی ۱ تا ۵۰۰ رویداد می‌پذیرد. همهٔ رویدادها پیش از نوشتن اعتبارسنجی می‌شوند؛ وجود ورودی نامعتبر باعث رد کل درخواست می‌شود. عملیات گروهی تراکنش چندسندی نیست: در خطای اتصال/نوشتن ممکن است بخشی ثبت شده باشد. پاسخ خطای دیتابیس `503` است؛ پیش از ارسال مجدد، رکوردها را بررسی کنید.

زمان ورودی باید timezone داشته باشد؛ ذخیره و خروجی UTC با دقت میلی‌ثانیهٔ MongoDB است. `source` و `message` خالی پذیرفته نمی‌شوند. سطح‌ها `DEBUG`، `INFO`، `WARNING`، `ERROR` و `CRITICAL` هستند. `attributes` یک شیء JSON سازگار با BSON تا ۱ MiB است. فیلدهای اضافی سطح اصلی رد می‌شوند. بدنهٔ بسیار بزرگ باید در استقرار آینده در reverse proxy محدود شود.

## ساختار

```text
app/
  main.py            # ساخت برنامه، چرخهٔ اتصال و مدیریت خطا
  api/logs.py        # مسیرها و اکشن‌های Swagger
  core/config.py     # تنظیمات محیط
  db/session.py      # دسترسی درخواست به دیتابیس
  models/log.py      # ساختار سند و تبدیل خروجی ذخیره‌سازی
  schemas/log.py     # قراردادها و اعتبارسنجی ورودی/خروجی
  services/logs.py   # توابع ثبت، جست‌وجو و خواندن
 tests/test_api.py   # تست‌های یکپارچه با MongoDB واقعی
 compose.yaml       # MongoDB با نسخه و digest مشخص
 requirements.lock  # نسخه‌های دقیق وابستگی‌ها
 docs/roadmap.fa.md  # نقشهٔ فازهای بعد
```

## تست

با MongoDB فعال:

```bash
.venv/bin/python -m pytest -q
```

تست‌ها از دیتابیس‌های موقت مستقل `siem_test_<uuid>` استفاده می‌کنند و پس از اجرا همان دیتابیس‌ها را حذف می‌کنند. تنظیم اتصال تست از متغیرهای محیط/`.env` خوانده می‌شود؛ از سرور توسعه استفاده کنید. دادهٔ دیتابیس اصلی `siem` توسط تست حذف نمی‌شود.

فاز اول فقط ورود JSON ساختاریافته و مشاهده را پوشش می‌دهد. فایل CSV، syslog، ویرایش/حذف لاگ، تشخیص تهدید، هشدار و اتصال پنل هنوز پیاده نشده‌اند.
